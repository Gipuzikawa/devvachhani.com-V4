## Migration plan

- Source: local `src/data/content.ts` plus page/shell editorial copy. Snapshot all
  relevant source files before transforming; no remote extraction credentials.
- Scope: three projects, three discipline documents, one Work singleton. Join the
  F-35 card and placeholder detail; retain the other cards' disabled detail pages.
  No article, settings, Home or About import yet. No assets exist to upload: retain
  seven archival placeholder figures and their ratios/captions.
- Model: project metadata with discipline references, optional enabled detail,
  milestone/tool/spec/reflection/figure/section-heading objects; Work singleton.
  Save incomplete drafts, require enabled-detail fields at publication.
- Identity: follow the approved project plan over migration-skill defaults:
  ordinary IDs generated by Sanity, lookup by unique source key, fixed singleton
  ID only for Work. Never use source-derived ordinary document IDs or replace
  editor documents wholesale. Stable array keys and reference ordering survive reruns.
- Import: require explicit development dataset and phase. Default dry-run performs
  reads only. A shared server lock serializes writing runs; matching source keys
  are resolved under that lock. Missing entities are created in dependency order.
  Existing published or draft records are skipped and differences reported.
- Updates: optional reviewed manifest identifies exact documents, revisions and
  source hashes. Reject ambiguous records, drafts, unmatched manifests and changed
  revisions; update only managed fields with revision guards.
- Verification: tests for parity, references, placeholder/detail flags, dry-run,
  rerun idempotence, editor edits/drafts, ambiguity, lock contention and stale
  manifests. TypeGen, Studio/frontend/server checks and build. Live writes remain
  development-only and require deployed schema; record local and live evidence separately.
- Cutover: unchanged six portfolio routes, no redirects or production writes.
  Public page rendering, responsive images and domain draft/publish checks follow
  in task 1.2 after this foundation is reviewed.
